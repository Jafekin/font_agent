一、选题的依据
1.1  选题背景与应用价值
本选题选题源于古籍数字化保护与智能化整理的实际需求。随着图书馆、档案馆与研究机构持续推进古籍影像采集与开放，海量古籍材料以图片形态快速累积，但古籍页面普遍存在字体异体多、版式结构复杂、墨迹不均与破损遮挡等问题，导致人工释读、著录补全与版本比勘成本高、效率低。与此同时，多模态大模型虽能对古籍图像进行内容描述与生成分析，但在学术研究场景中仍面临结论缺少稳定证据链、引用不可追溯、跨页语境不足等局限，难以满足“可复核、可比勘”的专业要求。因此，本选题拟在既有 RAG 基线能力之上，引入 GraphRAG 的图结构索引与证据组织方式，并采用 Agentic 架构将检索、版式/识别与引用核验等环节工具化，形成面向古籍图片的可追溯识别分析技术路线。
本选题在方法层面具有以下意义。其一，从检索范式上实现由“向量相似召回”的 naive RAG 向“实体关系约束检索”的 GraphRAG 演进：将题名、卷次、版本、馆藏、页面与版式特征等要素显式建模为图谱节点与关系，使检索过程能够通过关系路径与属性约束贴合目录学、版本学的组织逻辑，从而提升检索结果的语境一致性与解释性。其二，在生成可靠性上强化“结论—依据—来源”的证据闭环：通过将模型输出与图谱中的稳定标识和引用路径绑定，并引入引用一致性校验与证据覆盖检查，降低大模型幻觉风险，增强报告的可核验性与可复现性。其三，在系统方法论上体现 Agentic 思路对复杂任务的支撑价值：古籍识别分析往往包含版式识别、候选版本定位、语境补全与多轮核验等环节，采用智能体将这些环节封装为可调度的 skills，支持规划、回溯与过程记录，为构建可观测、可迭代优化的古籍智能体提供理论与工程统一的实现框架。
1.2  国内外研究现状分析
古籍图像智能分析作为数字人文与计算机视觉交叉领域的重要研究方向，近年来在深度学习技术的推动下取得了显著进展。然而，古籍特有的复杂性、多样性和历史性特征为技术应用带来了诸多挑战。本部分将系统梳理古籍图像识别与分析的技术发展现状，并深入分析当前面临的主要技术瓶颈，为后续构建可追溯、可复核的智能分析方案提供依据。
1.2.1 技术发展现状
古籍光学字符识别（OCR）技术已从传统方法转向基于深度学习的范式。典型流程包括图像预处理、版面分析、文本识别和后处理[1]。深度学习模型，特别是卷积神经网络和循环神经网络，已成为解决古籍文字识别问题的主流方法，显著提升了识别准确率并降低了应用门槛[1]。针对版面分析这一关键环节，当前方法主要分为三类：一是基于物体检测的方法，直接检测文档区域或文本行；二是基于实例分割的方法，利用全卷积网络进行像素级预测；三是结合关系推理的方法，如图神经网络，用于分析像素或部件间的复杂关系，在处理表格等结构化内容时表现更优[1]。
多模态大语言模型为古籍数字化研究带来了新的突破。它们能够同时处理文本、图像等多种模态信息，在处理插图古籍时，尤其擅长分析图像与文本之间的关联，从而深化对内容及其历史文化背景的理解[2]。一项针对17个主流多模态大模型的基准测试（BABMLLM）系统评估了它们在古籍处理任务中的表现，涵盖四个能力层级：语言理解与翻译、文本识别、多模态语义理解以及综合多模态推理[2]。评估结果显示，GPT-4o在各项任务中表现均衡，综合排名第一；Qwen-omni-turbo在翻译和图文一致性判断方面表现出色；GLM-4V-Plus-0111则在文本识别任务上表现强劲[2]。
高质量、大规模的标注数据集是训练深度学习模型的基础。近年来，多个研究团队在此方面取得了进展。例如，中央民族大学构建了一个面向OCR的满文古籍单词数据集，包含24,280张图像，涵盖2,428个独特的满文单词[3]。该数据集采用半自动化采集方法，结合计算机辅助技术与人工核验，并引入了图像质量筛选和标注复核机制，以确保数据质量4。此外，学界还构建了如TKH（高丽藏数据集）、MTH/MTH v2以及甲骨文数据集等，为不同文字和版式的古籍识别研究提供了数据支持[1]。
1.2.2 当前面临的主要技术挑战
深度学习模型依赖大规模标注数据，但古籍领域面临数据稀缺的困境。主要原因在于：标注工作需要专业的古文字学知识，人力成本高昂；珍贵古籍的数字化受版权和保存条件限制；数据质量要求高，需要严格的质控流程[1]。满文数据集的建设经验表明，采用半自动化方法结合人工核验，是应对高标注成本的一种可行路径[3]。
现有系统往往针对特定类型古籍训练，难以迁移到其他类型或不同历史时期的古籍上，领域适应性差[1]。对于满文、藏文等少数民族文字古籍的支持尤为有限[3]。古籍文献保存条件差导致的普遍性质量问题，如文字残缺、图像模糊等，也使得模型在低质量样本上的泛化能力面临挑战[3]。
一个关键的局限性在于，现有古籍图像分析系统大多作为“黑箱”运行，缺乏解释性和可信度保障。系统难以提供识别结果的证据链，无法清晰展示“结论—依据—来源”的推理过程，也缺乏可靠的置信度评估机制[2]。当识别结果出现错误时，用户难以追溯错误原因并进行复核，这严重限制了系统在严谨的学术研究和文化遗产保护中的应用价值。
1.2.3技术方案选择依据
GraphRAG作为检索增强生成（RAG）的高级形式，通过整合知识图谱等图结构数据，有效解决了传统RAG在捕获复杂数据关系、执行多跳推理和理解分层信息方面的固有局限[4]。GraphRAG能够将古籍图像中的离散要素（如题名、卷次、版本、馆藏信息、页面及版式特征）组织成由节点（实体）和边（关系）构成的图结构。这种表示方法不仅支持高效的语义检索，更重要的是能够显式地捕获和存储实体间复杂的多维关联。例如，一幅古籍绘画可能与多位作者、多个收藏流转记录、数枚印章以及多段题跋相关联，GraphRAG的图结构可以清晰地建模这些网络化关系，为深度分析提供基础[5]。图结构天然提供了明确的推理路径。在GraphRAG中，系统生成的每一个结论或答案都可以通过遍历图中的节点和边，追溯到其依赖的具体证据片段和逻辑链条[6]。这对于强调证据链完整性的古籍鉴定与研究至关重要。例如，在判断版本源流时，系统可以展示“版本A → 基于 → 版式特征B → 匹配 → 参考版本C”的完整可视化路径。这种透明度大幅提升了分析结果的可信度和可复核性。
而Agentic AI架构的核心在于赋予系统自主规划、调用工具、执行多步任务并进行反思的能力。gentic架构能够将古籍分析中的各项子任务（如图像分割、文字识别、印章匹配、文献检索、引文核验）封装为可被智能体调用的标准化工具（Skills）[7]。一个两层级的大语言模型代理（如分类器和分析器）可以理解用户的复杂查询，将其分解为一系列原子任务，
并动态调度相应的工具模块执行[5]。这种设计使得系统能够灵活、自动化地处理从图像预处理到综合判断的完整古籍分析链条。通过强制要求智能体在生成最终答案前必须调用检索、验证等工具获取外部证据，并将这些证据作为上下文提供给大语言模型，Agentic架构将模型的生成过程牢牢“锚定”在可信的事实基础上[8]。例如，在引文验证任务中，采用“零假设验证协议”的智能体系统会对每一处引用进行独立的多数据库交叉核验，从而将幻觉和错误引用降至最低[8]。
传统古籍研究方法高度依赖研究者的个人学识和经验，存在主观性强、可重复性低、知识传承困难等挑战。而基于规则或传统机器学习的方法，则难以灵活处理古籍中千变万化的样式和复杂的历史语境。GraphRAG与Agentic架构的结合，通过结构化的知识表示、自动化的关系推理和模块化的任务执行，为古籍分析带来了更高的客观性、一致性和系统性14。
在可追溯性方面，传统学术写作中的引证虽有一定规范，但验证过程繁琐。新技术方案通过架构层面的设计确保了可追溯性。例如，AI驱动的引文审计系统通过让智能体独立验证每一处引用，在测试中实现了超过91.7%的验证率，且假阳性率低于0.5%13。这为古籍分析中同样高要求的引证与核验提供了可靠的技术范式。

二、研究内容和方法（不少于1000字）
2.1  研究内容与目标
本选题面向“古籍图片→可追溯分析结论”的端到端流程，开展基于 Agentic GraphRAG 的古籍识别分析技术研究。具体包括：①古籍多源数据与元数据规范化：对页面图片、题名/卷次/版本/馆藏等元数据及版式特征进行统一字段抽取与清洗，形成可构图的数据底座；②GraphRAG 索引构建：将“文献—卷—页—版本—馆藏—版式指纹/实体”建模为图谱节点与关系，支持按关系路径与属性约束检索，并与向量检索形成混合召回；③智能体（Agentic）编排：把图检索、向量检索、OCR/版式分析、引用核验与报告生成封装为可调用 skills，设计面向任务目标（释读/著录补全/版本判定/修复建议）的工具选择与多轮回溯策略；④可追溯输出与评测：输出结构化报告（结论、置信度、证据片段、引用清单、证据路径），并建立针对检索质量、引用一致性与系统效率的评测方法。
总体目标是构建一个“可解释、可复核、可扩展”的古籍智能体原型系统：在古籍图片输入条件下，系统能够自动完成版式/内容线索提取，基于 GraphRAG（必要时结合向量检索）定位同源或近缘证据，生成带引用与证据路径的分析报告，并能记录智能体的工具调用过程以支持复盘与迭代优化。
技术指标层面，系统层面应完成 GraphRAG 索引的构建与在线查询，支持将“文献—卷—页—版本—馆藏—版式特征/实体”等要素以图结构存储并可按关系路径与属性约束检索，同时提供与向量检索的混合召回能力，确保每次检索结果均能返回稳定的文献/页面标识及对应证据路径，用于解释命中原因。生成层面要求输出结构化报告（结论、依据、置信度、引用清单与证据片段），并实现引用一致性校验：报告中的引用项必须可解析并映射到索引中真实存在的节点/页面记录，引用可追溯与存在性校验通过率达到可验收水平（例如不低于 95%）。稳定性层面要求端到端流程在预设测试集上具备较高任务完成率：对典型任务（如文献类型判定、题名/卷次线索抽取、相似版本候选推荐、破损与修复建议）能够稳定返回结果且包含引用，整体成功率达到可验收水平（例如不低于 90%，以无异常返回且引用完整为准），并具备明确的异常处理与降级策略。

2.2  拟采取的研究方案
本选题将围绕“古籍图片输入—证据检索—可追溯生成—引用核验—过程可观测”的闭环目标组织研究与实现。首先开展需求分析，明确系统面向的核心使用场景与输出形态：以古籍研究与整理流程为参照，抽象出文献类型判定、题名/卷次/版本线索抽取、相似版本候选定位、破损与修复建议等典型任务，统一定义输入（古籍图片、可选提示词/年代/出处等）、输出（结构化报告、引用清单、证据路径、置信度）以及可复核要求（引用可追溯、结论有依据、过程可复盘），并据此确定数据组织方式（页面级与文献级元数据、版式特征、OCR 结果、索引文件/图谱存储）与评测指标（检索命中、引用一致性、端到端成功率、性能开销）。
在理论与技术方法上，采用“GraphRAG + 混合检索 + Agentic 编排”的总体思路：一方面构建面向古籍的知识图谱索引，将文献—卷—页—版本—馆藏—题跋/注疏线索与版式指纹等要素建模为节点与关系，支持按关系路径扩展（例如从页面追溯到卷次与版本链路）与按属性过滤（例如限定馆藏、版本类型、版式特征范围），形成 GraphRAG 检索器；另一方面保留图像/文本嵌入的向量检索能力，用于解决“图谱关系未覆盖或元数据稀疏”场景，并设计混合召回与重排策略（如先图约束候选集再向量排序，或图检索与向量检索并行后融合 Top-K）。在生成阶段采用结构化 Prompt 与模板化输出，将“结论字段—证据片段—引用条目—证据路径”强约束到统一格式，并加入引用一致性校验模块：对生成引用逐条校验其在索引/图谱中的存在性、ID 映射正确性与证据覆盖情况，必要时触发补检索或降级回答，从机制上降低幻觉并提升可复核性。为支持复杂任务流程，采用 Agentic 架构将 OCR/版式识别、GraphRAG 检索、向量检索、重排、引用核验与报告汇总封装为 skills，并设计轻量的规划与回溯策略（如基于任务类型选择检索工具、证据不足时追加检索、引用失败时回退重组），同时记录每轮工具调用与中间结果以实现可观测与可复盘。
软硬件开发平台方面，软件以 Python 3.10+ 为主语言，Web 端基于 Django 提供上传与 API 服务，数据处理与索引构建以 NumPy/JSON 为基础，图谱存储可选轻量方案（如 SQLite/本地文件图结构）或图数据库（如 Neo4j）以满足关系查询与路径解释；OCR/版式识别模块可复用 PaddleOCR 管线输出列数、行数、边框等版式指标，并作为图谱属性与检索过滤特征；向量嵌入模块复用现有多模态嵌入（如 Chinese-CLIP）生成统一向量表示。硬件平台以普通开发机为基准，优先保证在无 GPU 环境可运行的可用性，同时提供可选 GPU 加速配置以提升 OCR 与嵌入推理效率；运行参数将以“可交互响应、可重复加载索引、可稳定批处理”为目标进行约束与验证。
技术路线总体为：数据准备与规范化（页面图片、元数据、OCR/版式特征）→ 图谱建模与 GraphRAG 索引构建（节点/边/属性、关系路径定义、查询接口）→ 混合检索模块实现（图检索/向量检索/融合重排）→ 结构化生成与引用一致性校验（模板化输出、引用映射与核验、证据不足回退）→ Agentic 编排与可观测日志（skills 封装、策略控制、全链路记录）→ 评测与迭代优化（检索质量、引用通过率、端到端成功率、性能开销对比）。最终形成可运行原型系统与可复现实验结果，为后续扩展更复杂的图谱实体、增量索引与更强的智能体规划策略打下基础。
2.3  预期成果与创新性
本选题预期形成可运行的“基于 Agentic GraphRAG 的古籍识别分析原型系统”及配套实验与文档成果。成果形式上，交付内容包括：（1）一套面向古籍图片的 GraphRAG 索引与构建工具链，可将文献—卷—页—版本—馆藏及版式特征等信息构建为图结构并提供查询接口；（2）混合检索与结构化生成模块，实现图检索与向量检索融合召回、证据重排、结构化报告输出与引用一致性校验；（3）智能体编排模块，将 OCR/版式识别、GraphRAG 检索、向量检索、引用核验与报告汇总封装为可调度 skills，支持按任务目标执行、多轮回溯与全过程日志记录；（4）Web/API 演示系统，在现有上传分析流程基础上提供可交互体验与历史记录，支持对单页古籍图片生成带引用的 Markdown/JSON 报告；（5）配套开题/中期/结题文档与实验评测材料，包括数据说明、技术路线、关键实现、指标验证与案例分析。代码量方面，预计新增与改造代码以“可复用模块 + 可运行 demo”为目标，整体在万行级以内可控推进，同时沉淀若干可复现实验脚本与配置文件以便复现结果。
创新性方面，本选题创新点主要体现在三个层面：其一，面向古籍场景引入“图谱化证据组织”的 GraphRAG 思路，将传统 RAG 的相似度检索提升为“实体关系 + 属性约束 + 路径解释”的证据检索方式，使检索结果更符合目录学/版本学的知识结构，并能够输出可解释的证据路径；其二，提出“引用一致性校验 + 可回退生成”的可靠性机制，将生成内容与图谱/索引中的稳定标识绑定，对引用可追溯性进行自动核验，并在证据不足或引用失败时触发补检索或降级策略，从工程上降低幻觉、增强可复核性；其三，采用 Agentic 架构把古籍分析拆解为可调度 skills（版式识别、图检索、向量检索、融合重排、引用核验、报告汇总），实现面向任务目标的流程编排与过程可观测记录，为后续扩展更复杂的图谱实体、增量索引与更强的规划策略提供可迭代的系统框架。整体而言，创新性不在于单一算法的“更复杂”，而在于面向古籍研究的证据链约束、图结构检索与智能体编排的系统级融合，从而实现“可解释、可追溯、可复盘”的古籍智能体原型。
2.4  进度计划
第1周：完成开题准备与需求分析，明确研究问题、目标用户与使用场景，定义输入输出（古籍图片/提示词→结构化报告+引用清单+证据路径）、验收指标与数据来源，梳理现有系统可复用模块与改造边界。
第2周：完成数据与元数据规范化方案，确定页面级/文献级字段（题名、卷次、版本、馆藏等）、版式特征字段与引用ID规则，制定清洗与抽取流程，形成可构图的数据样例集。
第3周：完成图谱建模设计，定义核心实体与关系（文献-卷-页-版本-馆藏-版式/实体词条等）及属性约束，输出图谱 schema、典型查询用例与证据路径解释规则。
第4周：实现 GraphRAG 索引构建脚本（初版），将 metadata 与版式特征入库/入图，完成最小可用的节点/边生成与持久化，形成可复现的构建流程与配置。
第5周：实现 GraphRAG 查询接口（初版），支持按页/卷/版本链路检索与属性过滤，输出候选证据、节点ID与可解释路径，完成基本单元测试/样例验证。
第6周：梳理并适配向量检索模块，统一嵌入生成、索引加载与 Top-K 返回结构，完成向量结果到引用字段/页面ID的映射，为混合检索接口对齐。
第7周：实现混合检索策略（初版），完成“图约束候选集→向量排序”或“图检索与向量检索并行→融合重排”的可运行方案，输出统一证据列表与分数。
第8周：建立结构化 Prompt 与报告模板（Markdown/JSON），定义结论字段、证据片段、引用清单、置信度与格式规范，保证输出可解析且字段稳定。
第9周：实现引用一致性校验模块，对生成引用进行存在性与ID映射核验，补齐引用格式约束与错误提示机制，确保“结论—依据—来源”可追溯。
第10周：实现回退/补检索机制（轻量），在证据不足或引用校验失败时触发追加检索、调整 Top-K 或降级回答策略，提高端到端稳定性。
第11周：完成 Agentic 架构设计与技能封装，将 OCR/版式识别、GraphRAG 检索、向量检索、融合重排、引用核验、报告汇总封装为 skills，定义状态与中间产物结构。
第12周：实现智能体执行流程（初版），支持按任务类型选择技能与顺序，跑通端到端闭环（图片输入→证据检索→结构化报告输出），并接入 Web/API 演示入口。
第13周：完善可观测性与日志记录，落地每轮工具调用日志、检索参数、命中证据、引用与中间结果导出（JSON/文件），支持复盘与误差定位。
第14周：建设评测数据集与评测口径（轻量），选取代表性页面与任务样例，定义检索命中、引用通过率、端到端成功率、响应时间/资源占用等指标的计算方法。
第15周：开展对比实验与消融分析，至少完成“仅向量RAG vs GraphRAG/混合检索”“无校验 vs 有校验”“无智能体 vs 有智能体”的对比，汇总定量结果与典型案例。
第16周：系统优化与工程收敛，处理性能瓶颈与稳定性问题，完善异常处理、配置管理与可复现实验脚本，形成可交付的运行说明与演示流程。
第17周：撰写论文主体与配图，完成方法与系统实现、实验与案例分析章节，补齐相关工作、讨论与局限性，整理关键图表与流程图。
第18周：论文定稿与答辩材料准备，整理代码/文档交付清单与演示脚本，完成PPT、可能问答与风险说明，进行最终验收与归档。
